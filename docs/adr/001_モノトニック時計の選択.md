# ADR-001: タイマーAPIの設計 - モノトニック時計（RAW）の選択

**Status:** 承認・実装完了
**Date:** 2025-10-25
**Category:** タイマー・タイミング制御

## 概要

video-proto プロジェクトの `platform_get_time()` APIの戻り値の型と特性について決定した。

**決定内容：**
`double` 型でモノトニック時計（調整なし/RAW）を返すAPIに統一する。各プラットフォームで以下を採用：
- **macOS**: `CLOCK_UPTIME_RAW`
- **Windows**: `QueryPerformanceCounter()`
- **Linux**: `CLOCK_MONOTONIC_RAW`

## 背景

プロジェクトではゲームフレーム制御とビデオアニメーション制御が主用途。タイマーAPIの選択は以下の要素の検討が必要だった：

1. **データ型の選択**
   - `double` （秒単位、浮動小数点）
   - `uint64_t` （ナノ秒またはマイクロ秒単位、整数）

2. **時計の種類**
   - 絶対時刻（wall clock）：システムの壁時計、NTPで調整される
   - モノトニック時計：単調増加を保証
     - 調整あり：NTPで周波数調整される
     - 調整なし（RAW）：ハードウェアクロック直接

3. **プラットフォーム間の精度**
   - macOS: `CFAbsoluteTimeGetCurrent()` (絶対時刻, double)
   - 各プラットフォームで異なるAPIが存在

## 比較検討

### `double` vs `uint64_t`

| 項目 | double | uint64_t |
|------|--------|----------|
| 直感性 | ✅ 秒単位で計算しやすい | ❌ ナノ秒/マイクロ秒→変換必要 |
| 精度（60fps） | ✅ ~119ns（十分） | ✅ ナノ秒精度 |
| 32bit/64bit | ✅ 常に8バイト | ❌ プラットフォーム依存 |
| 既存コード互換性 | ✅ 互換性維持 | ❌ 全て書き換え |
| 計算の複雑性 | ✅ シンプル | ❌ 単位変換が必要 |

**決定：`double` を採用した理由**

1. フレーム間隔計算が直感的：`dt = current - last` （秒単位）
2. 既存コードに対する影響が最小
3. 52bit仮数部で30年間にわたってナノ秒精度を維持
4. GLFW等の標準ライブラリと同じ選択

### 時計の種類の選択

#### 絶対時刻（CFAbsoluteTimeGetCurrent）
**特性**: システムの壁時計、2001年から経過した秒数
- **問題点**：NTPによるシステム時刻調整で時刻が巻き戻る可能性
- **不適合**：`dt = current_time - last_time` が負になる可能性
- **用途に合わない**：ゲーム内タイミングには不要

#### モノトニック時計（調整あり）
**特性**: 単調増加を保証、NTPで周波数調整される
- **特性**：周波数が変化（slew）するが逆戻りしない
- **影響**：1時間で数ミリ秒のずれ（ゲーム用途では許容範囲）
- **採用しなかった理由**：ゲーム/アニメーション用途では不要な複雑性

#### モノトニック時計（調整なし/RAW）✅ **採用**
**特性**: ハードウェアクロック直接、NTP調整の影響なし
- **精度**：一貫した高精度（マイクロ秒以下）
- **予測性**：ハードウェアのみなので動作が予測可能
- **利点**：
  - 短時間の精度が最重要なフレーム制御に最適
  - NTP調整による変動がない
  - デバッグ時の再現性が高い

**選択根拠**：
- ゲーム/ビデオ制御は短時間での高精度が必須
- NTP調整の影響を完全に排除
- ハードウェアクロック直接なので動作が予測可能

## プラットフォーム間の精度比較

### 各APIの解像度

| Platform | API | 精度 | 調整 | 備考 |
|----------|-----|------|------|------|
| Windows | `QueryPerformanceCounter()` | ~100ns | なし | HPET等ハードウェア依存 |
| macOS | `clock_gettime_nsec_np(CLOCK_UPTIME_RAW)` | ~1ns | なし | ナノ秒精度、macOS 10.12+ |
| Linux | `clock_gettime(CLOCK_MONOTONIC_RAW, ...)` | ~1ns | なし | 標準API |

### フレーム制御への影響

60fps = 16.67ms/フレーム との比較：

```
Windows QPC:   100ns = 0.0001ms (誤差: 0.0006%)  ✅ 十分
macOS/Linux:     1ns = 0.000001ms (誤差: 0.000006%) ✅ 過剰なほど十分
```

**結論：** 全プラットフォームでマイクロ秒以下の精度が得られ、60fps/120fps制御に十分すぎるほど精度がある。

## ネットワークゲームへの将来対応

将来ネットワーク同期が必要になった場合の想定設計：

### 設計原則：関心の分離

```zig
// ゲーム状態構造体
const GameState = struct {
    // ローカル時刻（フレーム制御用）
    local_time: f64,           // platform_get_time() で取得

    // サーバー時刻（同期用）
    server_frame: u32,         // サーバーのフレームカウンタ
    server_time: f64,          // サーバーから受け取る
    time_offset: f64,          // オフセット: サーバー時刻 - ローカル時刻
};
```

### 同期パターンの選択肢

1. **フレームカウンタ（シンプル）**
   - サーバーとクライアントが同じフレームレート保証
   - フレーム単位での同期

2. **補間（標準）**
   - 最後のサーバーアップデートと現在の状態を補間
   - ネットワーク遅延を隠蔽

3. **外挿補間（高度）**
   - サーバーから受け取った速度情報で予測
   - 最も滑らかに見える（予測外れの危険性あり）

### 設計上の利点

- **ローカル側**：`platform_get_time()` (RAW時計) で正確なフレーム制御
- **同期側**：別層で `time_offset` を管理して外部と同期
- **メリット**：各層の責務が明確で、既存コードに影響なし

## 決定による影響

### ✅ 利点

1. **一貫した高精度**
   - 全プラットフォームでマイクロ秒以下
   - NTP調整の影響なし

2. **フレーム制御に最適**
   - `dt = current - last` で常に正の値
   - 負の時刻差がないため安定したシミュレーション

3. **シンプルな実装**
   - プラットフォームごとの差異を吸収
   - 利用側は `double` で単純に計算可能

4. **スケーラビリティ**
   - ネットワーク対応時に上位層で同期ロジックを追加可能
   - 既存コード（フレーム制御層）に影響なし

5. **デバッグ性**
   - NTP調整がないため動作が再現可能
   - フレーム制御のデバッグが容易

### ⚠️ 考慮事項

1. **長時間実行時のドリフト**
   - RAW時計はシステム時刻と無関係
   - 数日実行後、NTP調整済みシステムクロックとずれる可能性
   - **対策**：ゲーム内のみで使用、外部との同期が必要な場合は別途管理

2. **サスペンド/スリープ時**
   - `CLOCK_UPTIME_RAW` はマシンスリープ中は停止
   - **評価**：ゲーム用途には自然な動作（スリープ中はゲームも停止）

3. **古いOS非対応**
   - macOS 10.12（Sierra）以降が必須
   - **評価**：現代環境ではほぼ問題なし

## 実装詳細

### platform.h のAPI仕様

```c
// 高精度モノトニック時刻を取得（秒単位、double型）
//
// 特性:
// - モノトニック: 時刻は単調増加し、決して逆戻りしない
// - 調整なし（RAW）: NTP等のシステム時刻調整の影響を受けない
// - 高精度: マイクロ秒以下の精度（プラットフォーム依存）
//   - Windows: ~100ns (QueryPerformanceCounter)
//   - macOS: ~1ns (CLOCK_UPTIME_RAW)
//   - Linux: ~1ns (CLOCK_MONOTONIC_RAW)
//
// 戻り値:
// - システム起動またはプロセス開始からの経過時間（秒）
// - 絶対値は意味を持たない（相対的な時刻差分の計算にのみ使用）
// - サスペンド/スリープ時の動作はプラットフォーム依存
//
// 用途:
// - フレーム間隔の計測: dt = current_time - last_time
// - アニメーション制御
// - ベンチマーク、プロファイリング
//
// 注意:
// - この時刻はシステムの壁時計（wall clock）とは無関係
// - ネットワーク同期が必要な場合は、別途サーバー時刻管理が必要
// - 長時間実行時、システム時刻とのずれが蓄積する可能性がある
double platform_get_time(void);
```

### 実装例

#### macOS (Objective-C)
```objective-c
// platform/macos/platform_macos.m
#include <time.h>

// 高精度モノトニック時刻を取得（調整なし）
double platform_get_time(void) {
    uint64_t ns = clock_gettime_nsec_np(CLOCK_UPTIME_RAW);
    return (double)ns / 1e9;
}
```

#### macOS (Swift)
```swift
// platform/macos-swift/platform_macos.swift
@_cdecl("platform_get_time")
func platform_get_time() -> Double {
    let ns = clock_gettime_nsec_np(CLOCK_UPTIME_RAW)
    return Double(ns) / 1e9
}
```

#### Windows (C)
```c
// platform/windows/platform_windows.c
#include <windows.h>

double platform_get_time(void) {
    static LARGE_INTEGER frequency;
    static BOOL initialized = FALSE;

    if (!initialized) {
        QueryPerformanceFrequency(&frequency);
        initialized = TRUE;
    }

    LARGE_INTEGER counter;
    QueryPerformanceCounter(&counter);
    return (double)counter.QuadPart / (double)frequency.QuadPart;
}
```

#### Linux (C)
```c
// platform/linux/platform_linux.c
#include <time.h>

double platform_get_time(void) {
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC_RAW, &ts);
    return (double)ts.tv_sec + (double)ts.tv_nsec / 1e9;
}
```

## 参考情報

### プラットフォームごとのタイマーAPI詳細調査

#### Linux

| API | 種類 | 調整 | 用途 |
|-----|------|------|------|
| `CLOCK_MONOTONIC` | モノトニック | 周波数調整あり | NTPと協調 |
| `CLOCK_MONOTONIC_RAW` | モノトニック | **なし** | フレーム制御 ← 採用 |
| `CLOCK_BOOTTIME` | モノトニック | 調整あり | サスペンド時間含む |
| `CLOCK_REALTIME` | 絶対時刻 | ジャンプあり | ログ、外部同期 |

#### macOS/iOS

| API | 種類 | 調整 | 用途 |
|-----|------|------|------|
| `CFAbsoluteTimeGetCurrent()` | 絶対時刻 | ジャンプあり | システム時刻 |
| `CACurrentMediaTime()` | モノトニック | 調整あり？ | メディア制御 |
| `mach_absolute_time()` | モノトニック | **なし** | ティックカウンタ |
| `clock_gettime_nsec_np(CLOCK_UPTIME_RAW)` | モノトニック | **なし** | フレーム制御 ← 採用 |

#### Windows

| API | 種類 | 精度 | 用途 |
|-----|------|------|------|
| `GetTickCount64()` | モノトニック | 15.6ms | タイムアウト判定 |
| `QueryPerformanceCounter()` | モノトニック | **~100ns** | フレーム制御 ← 採用 |
| `QueryInterruptTimePrecise()` | モノトニック | <1μs | Windows 10+ |
| `GetSystemTimePreciseAsFileTime()` | 絶対時刻 | ジャンプあり | 外部同期 |
